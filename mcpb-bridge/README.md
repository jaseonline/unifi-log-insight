# insights-plus-mcp-bridge (MCPB)

A local MCP server, packaged as an MCP Bundle (`.mcpb`), that bridges Claude to a self-hosted [UniFi Insights Plus](https://github.com/jmasarweh/UniFi-Insights-Plus) instance's `/api/mcp` endpoint over HTTPS — including optional Cloudflare Access service-token auth.

## Why this exists

Insights Plus's MCP endpoint is remote (HTTP/SSE), but Claude Desktop extensions run as local stdio processes. Previously this meant hand-editing `claude_desktop_config.json` with a raw `npx -y mcp-remote ...` command line, with three problems:

1. Credentials (bearer token, Cloudflare Access client secret) sat in **plaintext** in a config file on disk.
2. `npx` re-resolves the `mcp-remote` package from the npm registry on **every launch**, which has unbounded latency — on a slow or flaky connection this can exceed Claude Desktop's handshake timeout, making the server intermittently "fail to load" for reasons that have nothing to do with the remote server itself.
3. No automatic recovery if the upstream HTTP/SSE connection dropped mid-session.

This bundle fixes all three: credentials are collected through the host's configuration UI and stored securely (not in a plaintext config file); there's no `npx` and no registry round-trip — `@modelcontextprotocol/sdk` ships inside `node_modules` in the bundle itself; and the upstream connection is lazy (established on first real tool call, not at startup) and self-healing (an automatic reconnect-and-retry on a stale/dropped connection).

```
insights-plus-mcp-bridge/

```

## Building the bundle

```sh
npm install --production      # populates node_modules for bundling
mcpb validate manifest.json   # schema + icon check
mcpb pack . insights-plus-mcp-bridge.mcpb
```

`mcpb pack` respects `.mcpbignore` — `server/smoke-test.js`, this README, and VCS files are excluded from the shipped bundle; everything a running server actually needs (manifest, icon, server code, `node_modules`) is included.

## Testing without a real Insights Plus instance

```sh
node server/smoke-test.js
```

This spawns the real entry point as a child process (exactly like a host application would), sends it a genuine MCP `initialize` + `tools/list` over stdio, and asserts:

- `initialize` returns fast (well under the configured timeout) — proving the local handshake never depends on the (deliberately unreachable) upstream URL.
- A `tools/call` against the unreachable upstream comes back as a structured, informative error — never a hang, never a crash, never raw stdout corruption.

For a full end-to-end test against a real instance, install the bundle in Claude Desktop (double-click the `.mcpb` or drag it onto Claude Desktop's extensions settings) and fill in your real MCP Endpoint URL and Bearer Token when prompted.

## Configuration (collected by the host, not edited by hand)

| Setting | Required | Notes |
|---|---|---|
| MCP Endpoint URL | Yes | e.g. `https://insights.example.com/api/mcp` |
| MCP Bearer Token | Yes | From Settings → MCP inside Insights Plus |
| Cloudflare Access Client ID | No | Only if the endpoint is gated by a CF Access Service Token policy |
| Cloudflare Access Client Secret | No | Must be set together with the Client ID, or neither |
| Request Timeout (seconds) | No (default 30) | Raise this if your instance/network is slow, not fast |
| Verbose Logging | No (default off) | Extra stderr diagnostics; never logs secret values |

## Design notes for future maintenance

- **Never write to stdout except via the MCP SDK's transport.** Any stray `console.log` will corrupt the protocol stream and silently break the host connection. All diagnostic output goes through `logger.js`, which writes to stderr only.
- **Never log secret values.** `logger.js` redacts any configured secret value out of every log line, including serialized metadata objects, as defense-in-depth beyond just "don't pass secrets to the logger."
- **Prefer returning `isError: true` tool results over throwing** for `tools/call` specifically — this is what lets Claude see and reason about a failure ( e.g. "the remote server is down") rather than the whole exchange just failing silently.
- **The upstream Insights Plus MCP tool set can change independently of this bundle.** `manifest.json` declares the known tools (as of this bundle's version) for a nice settings-UI listing, but sets `tools_generated: true` and the server always forwards whatever `tools/list` the remote actually returns — so new tools added to Insights Plus show up automatically without a bundle update.
